# Phylax Agent & Evaluation Specification

This is the source of truth for what miners build, how validators run and score
them, and what the corpus must contain. It reconciles the whitepaper v2 with the
execution model the network actually runs.

## 1. The unifying principle

Detection is **intent versus behaviour**, not signatures. For every artifact
type: derive what the artifact *declares* it does, execute or analyse it under
instrumentation, and treat any deviation between declared intent and observed
behaviour as the signal of malice. The principle is uniform; the method is
per-track.

## 2. The submission model (code, not images)

A miner submits **code only**. There is no miner-supplied container image.

- `code` — the agent source, exposing the entrypoint (default `agent_main`).
- `entrypoint` — the function name the validator calls.
- `execution_api_key` — the miner's own inference key (funds the agent's LLM
  calls, routed through the validator's metered proxy).
- `inference_model` — optional preferred model.
- `agent_hash` — `sha256(code)`, and an ed25519 `signature` over the submission.

The `code` bytes are the hash-pinned artifact: the exact code the network
evaluates is the exact code the marketplace serves.

The validator runs that code inside a **validator-owned sandbox image**. Miners
never control the runtime, which removes the "wrong agent runs" and
"arbitrary attacker image on the host" failure modes in one move.

## 3. The agent contract

`agent_main(context) -> report` where `context` carries:

```
artifact_dir   path to the materialised artifact (read-only intent)
track          skills | mcp_servers | packages | repositories
nonce          per-task nonce (round seed + artifact ref)
probe          liveness probe inputs (see §6)
inference      { api, api_key, provider, model }  # proxy URL + miner key
```

The report is JSON with:

```
verdict   { decision: ALLOW|WARN|BLOCK, risk_score: 0-100 }
evidence  per-track evidence (see §5)
findings  [ { severity, category, title, description, file?, location? } ]
policy    recommended enforcement (optional)
```

Miners call inference only through `context.inference.api` (the metered proxy);
it is the sole outbound path.

## 4. What the validator safeguards (per execution)

Self-protection while running untrusted code:

- **Validator-owned image**, miner code mounted at `/task/agent.py`.
- **`--internal` docker network**; the agent's only reachable host is the
  metered inference proxy.
- **Hardening**: `cap-drop=ALL`, `no-new-privileges`, non-root user, memory/cpu/
  pids caps, tmpfs, ephemeral per-task container.

Anti-gaming on what the agent returns:

- Ground truth is never shown to the agent.
- Findings are bounded before scoring (no brute-forcing recall).
- Correctness is measured against held-out labels, not self-report.
- Inference is metered per task; an agent that produced a verdict with no
  inference and no probe is treated as not having done the work.

## 5. Per-track detection scope (what agents must catch)

Behavioural signals (agent detonates and observes) are the portable core;
metadata signals are supplied to the agent alongside the artifact.

| Track | Behavioural | Metadata |
|---|---|---|
| skills | hidden instructions / prompt injection, unauthorised data/system access, credential & env reads, network exfil, shell/eval, obfuscation, trigger-gated behaviour | author/source provenance |
| mcp_servers | malicious startup/shell commands, tool poisoning, tools acting beyond declared function, network/fs/env overreach, multi-step attacks | declared vs observed schema |
| packages | install/postinstall scripts, shell, eval, dynamic require, network, fs, env/secret reads, high-entropy strings, native code, obfuscated/minified, telemetry | typosquat, manifest confusion, malicious transitive deps, CVEs, ownership, deprecated |
| repositories | embedded backdoors/triggers, malicious CI/workflows, curl-pipe-to-shell, secret exposure in history, out-of-scope components, malicious NL instruction files | dependency-source risk, provenance |

## 6. Proof of execution (demoted to a liveness signal)

The primary anti-gaming mechanism is **correctness against held-out ground
truth** — a fabricated or empty report simply scores zero. Proof of execution is
a *secondary* liveness signal, not the sole gate:

- A fresh per-task probe is generated by the validator.
- Real inference traffic through the metered proxy is recorded per task.

A run with neither a satisfied probe nor recorded inference is treated as not
executed. Correctness still dominates the score.

## 7. Scoring (winner determination)

- **Correctness** `c = g · (1 − |risk − y*|)`, gated by proof of execution `g`.
- **Reliability** — a task counts only if the agent is *correct* on
  `ceil(ρ · r)` of `r` repeat runs (ρ = 0.5). "Correct" means the run's
  correctness clears a floor, not merely a non-zero score.
- **Quality threshold** τ = 0.6 gates eligibility.
- **Graduated weights** — top three per track split emissions 0.50 / 0.30 / 0.20.
- **Consensus** — stake-weighted median (Yuma), on chain. The server never picks
  winners; it records and reflects on-chain consensus.
- **Repositories** — findings are matched to ground truth semantically (file +
  fuzzy title/CWE + line window), scored on recall and clean-precision.

## 8. Rounds (server-scheduled)

Rounds are triggered by the server, not by block windows:

1. The server signals a round should run (per track).
2. The validator seeds the task set from the current block hash (unpredictable,
   reproducible), freezes agents by hash, screens copies.
3. It runs each agent's code in the validator-owned sandbox, scores against the
   corpus ground truth, produces signed attestations (SSSAs).
4. It POSTs per-agent signed results to the server and sets weights on chain.
5. The server records results, reads the metagraph for champion-per-track, and
   serves the champion's verdicts as marketplace attestations.

The server schedules and persists; the chain decides; validators score
independently.

## 9. Corpus requirements

Per track, a labelled set of known-good and known-bad artifacts:

- Each known-bad artifact labelled with its expected findings (title +
  description + location), covering the catch categories in §5.
- **Evasive samples are mandatory** — trigger-based, time-bombed, and
  environment-keyed payloads labelled malicious, so a detector that only watches
  benign behaviour fails on recall. This is what makes sandbox evasion
  structurally unrewarding.
- A held-out partition never shipped to agents or the public repo.
